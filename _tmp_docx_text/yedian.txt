摘要
随着互联网浪潮迅猛的推进，网络信息技术呈现出的社交方式愈来愈多样化，便利化。到目前时代几乎各个高校或企业都对于信息化的建设提出了更高的要求，而对于社交媒体而言，其形式呈现出百花齐放的态势。得利于各种轻微级的网页技术和框架的广泛应用，使得网络社区更加富有活力。其中论坛系统则是从互联网元年以来不断推陈出新，是一种是种提供在线讨论的程序，或由这些程序创建的以在线讨论为主的网站，其拉近了人们沟通意见发表观点的距离，是用户进行对话讨论的重要渠道。所以针对独立建设一个具有校园特色的BBS论坛，不仅可以展示出本学校的信息化建设的程度，还能展现出部分学校文化实力。本设计系统将根据高校的主要需求，构建校园论坛的大体框架与功能，以面向学生和老师获得更好的服务提供更优质的设计。
为此将传统的论坛设计理念融合进入到高校服务中，根据校园论坛的基本需求选择合适的架构选型，以此作为基础设计基于JavaEE技术的整个Web论坛系统。该系统通过以spring框架技术的整合，包括以springmvc，mybatis，mysql等多种技术整合，并且与前端jsp页面进行搭桥，取用Browser/Server架构构建Java的动态Web校园网站论坛系统，本系统总体内容分为前后台两个部分，针对不同用户身份做出不同的功能选择，前台功能主要包括注册用户的版块进行对帖子的发放、内容回复与收藏、个人信息资料的修改和处理。后台管理则是以管理员身份需要对各个模块进行管理。
整体系统简洁美观，用户通过浏览器可以进行对论坛网站的访问，基本功能完整健全，稳定性较高。完成系统的过程中，给出了该系统中的各个功能模块和数据库的具体实现思路，最后进行项目的总结和展望。
关键词：校园社区，论坛系统，spring，Web，MVC
Abstract
With the rapid development of the Internet, the social ways of network information technology are becoming more and more diversified and convenient. In the current era, almost all colleges and universities or enterprises have put forward higher requirements for the construction of informatization, and for social media, its form shows a trend of flourishing. Benefit from the wide application of various minor web technologies and frameworks, the network community is more dynamic. The forum system is from the Internet since the first year of continuous innovation, is a kind of program to provide online discussion, or created by these programs based on online discussion website, which closes the distance between people communicate opinions and opinions, is an important channel for users to discuss dialogue. Therefore, the independent construction of a BBS forum with campus characteristics can not only show the degree of informatization construction of the school, but also show the cultural strength of some schools. This design system will construct the general framework and function of the campus forum according to the main needs of colleges and universities, so as to provide better service for students and teachers to provide better design.
Therefore, the traditional forum design concept is integrated into the service of colleges and universities. According to the basic needs of the campus forum, the appropriate architecture selection is selected, and the whole Web forum system based on JavaEE technology is designed. Through the integration of spring framework technology, including springmvc, mybatis, mysql and other technologies, and bridging with the front-end jsp page, the system uses Browser / Server architecture to build a Java dynamic Web campus website forum system. The overall content of this system is divided into two parts : front and back, and different functional options are made for different user identities. The front function mainly includes the distribution of posts, content reply and collection, and modification and processing of personal information by the registered user ’ s block. Background management is to manage each module as an administrator.
The whole system is simple and beautiful. Users can access the forum website through the browser. The basic functions are complete and sound, and the stability is high. In the process of completing the system, the specific implementation ideas of each functional module and database in the system are given. Finally, the summary and prospect of the project are carried out.

第1章 引言
研究背景和意义
在互联网飞速发展不断变化的几十年以来，当前社会正在处于急剧变化的信息化转型状态，转型所带来的人口流动增强，数字经济发展，促进了众多网络论坛，BBS等网络社区的日新月异。网络论坛开始逐渐发展成为了人们对于语言交流，意见转接，信息表达的一种主要实现平台。最初的电子公告板网页的出现开辟了一种新的信息交流形式。随着时间的推移，技术的更新换代变成了功能更加齐全发达的在线论坛网站。目前市面上所熟知的大型企业级论坛网如天涯社区、贴吧、知乎等，在日常生活中影响着社会群体等各个方面，这些论坛因为能够承载非常巨大的日常访问量，无论是各种信息的及时处理能力还是多个不同平台的系统兼容性都能够得到相当的保障，但是国内的这些论坛平台存在的问题主要是功能太过冗余，信息量过于繁琐或者界面过于花哨不能够使用户得到良好的体验性[1]。在国外的平台主要有twitter，reddit等大型论坛，这些论坛对于话题的讨论形式基本上都有较强的针对性，某一个论坛中对于不同的话题内容都进行了很详细的分割和细化，各种领域的话题讨论都进行了严格的区分并拥有专业的社区管理者进行对于内容的审核和把关，需求方向更加专一。紧随着未来时代的信息变现，学生尤其是作为大学生一类的群体对于某些知识的获取方法已不仅仅局限于纸质书本，期刊之间。学生们能够通过越来越进化的网络环境，通过更加简易的方式在互联网之中收获到更充足的知识内容。而且除了学习之外，学生们还有其他日常活动需求，如交友闲聊，社团管理，物品交易。如果仅仅使用QQ微信等平台往往会因为信息的大量沉淀导致信息的滞后性而使得想要做的事情没有得到实现。此校园论坛平台可以服务于学生之间的生活心得交流，学习意见分享，或者是成立各种兴趣小组来将志同道合的人群组织起来。其中还拥有社区管理人员对各个板块中的帖子发布能够进行详细认真的审核和监督，能够及时处理好一些不良信息和垃圾内容
本论坛平台旨在为全体用户提供一种实用性强，操作界面简洁易于使用，界面美观清楚的校园社区论坛平台[2]。
1.2 国内外研究现状
1.2.1 国外研究现状
第一个公共拨号BBS 由Ward Christensen和Randy Suess开发。两人开始了计算机公告板系统或CBBS的初步工作。该系统的出现主要是由于一台备用的 S-100 总线计算机和一个早期的 Hayes 内部调制解调器。现代网络论坛起源于公告板，也就是所谓的计算机会议系统，是拨号公告板系统的技术演进。从技术角度来看，论坛或板是管理用户生成内容的Web 应用程序。早期的基于网络的论坛可以追溯到 1994 年，W3 联盟的 WIT 项目从那时开始，创建了许多替代方案。虚拟社区的内容通常围绕有固定用户的论坛发展。技术、电子游戏、体育、音乐、时尚、宗教和政治是论坛主题的热门区域，但有大量主题的论坛。互联网上流行的互联网俚语和图像在互联网论坛中广泛使用。
论坛网页在Internet上随处可见，并使用各种编程语言来编写，例如PHP、Perl、Java和ASP。帖子的配置和记录可以存储在文本文件或数据库中。每个包都提供不同的功能，从最基本的提供纯文本帖子到更高级的包，提供多媒体支持和格式化代码。许多软件包可以轻松集成到现有网站中，以允许访问者对文章发表评论。
论坛由树状目录结构组成。顶端是“类别”。一个论坛可以划分为相关讨论的类别。类别之下是子论坛，这些子论坛还可以有更多的子论坛。主题（通常称为主题）属于最低级别的子论坛，这些是成员可以开始讨论或发帖的地方。从逻辑上讲，论坛被组织成一组有限的通用主题（通常有一个主要主题）。
1.2.2国内研究现状
我国内陆的第一个BBS论坛建立于上个世纪90年代初，相较于国外的网络环境，本国的互联网基础起步较慢，从最开始难以普及的网络普及使得关于网络社区的总体访问量变得极少。但随着国内整体经济的迅速发展，个人群体逐渐的能够负担其一台个人计算机并能够进入到互联网的世界之中，所以一些网络论坛就如雨后春笋般逐步建立起来并慢慢的成为各种主题的虚拟社区，此后论坛网站不断得推陈出新，功能变得越来越强大，性能承载量也变得的越来越大，涵盖的话题领域也越来越丰富。这种繁荣的网络社会现象一直持续到达90年代末期。随后在新世纪初的互联网经济的打击下，非常之多的网络论坛社区的因缺乏维护未能幸免逐渐消失在互联网的历史浪潮之中。但又随着一些大型互联网企业的崛起，一些企业级的论坛平台走向了成熟的阶段并且取得了巨大的用户群体数量并且到目前为止也是经久不衰。然而，一些小型的地域性论坛平台却相较于大型论坛比较缺失，专注于校园的网上虚拟社区也屈指可数，相比于大型论坛的信息冗余，商业化过重的缺点。建立一种小型的论坛平台是对校园师生群体很有意义的一步。
1.3 主要内容和工作安排
本项目系统在进行合理的调查研究，结合用户群体的深层分析，相较不同于市面上一般性质的商业论坛，设计出了简洁实用，符合用户操作习惯的平台界面，并达到界面交互友好，便利快捷的预期效果。
在本次的项目设计过程之中，将准备计划和完成一个具有某种特色，并且符合于大学校园特色的功能丰富的个性化学院BBS论坛系统，对于不同所属的高校仍然还有其重要内涵和基本意义，学校的信息化建设也应该在这些相关的方面不断地继续提供帮助，努力打造成一种覆盖更加全面和更加高效的论坛系统， 也许能将成为高校的一种文化的体现。使得这样的论坛可以更加方便服务于广大师生群体提供为一种沟通交流的平台和提高信息收集化的共享程度，将不仅限于提升学生们开放的视角，同时也能够丰富学生之间的复杂情感，对于校友间的沟通能够提高人们之间的感情结构，拉近交流的距离都是鉴于此变得更加有益。与此同时，一些少数具有情感障，或者出现心理问题的同学也能够通过到论坛网页中加以倾诉或发泄自己的话语也具有可能将此心理症状得到有效的缓解。最后将维护论坛社区的健康发展，管理者需要进行严格的监督审核处理工作。能够依据国家相关的法律法规将一些非法信息或者垃圾信息进行及时的杜绝，能够为整体用户创造一个健康交流的活力平台。

第2章 技术选型
2.1 技术选型简介
本项目平台作为是在浏览器端的web网页，以B/S架构模型为基础通过建立表示层、业务层和数据持久层三层结构。前端主要采用的是基本的html5，css，JavaScript，JQuery，而后端的技术栈主要有JavaEE，Spring，SpringMVC，Mysql，Mybatis等。基本的开发环境是JetBrains旗下的IntelliJ Idea。
2.1.1 JSP页面
JSP（全称Jakarta Server Pages）是由升阳公司独立创造的一种动态网页技术标准。JSP能够部署在本地或网络服务器，是用来响应从客户端中传输的请求，然后通过所请求到的数据内容将自动生成HTML、XML或者其他格式内容的Web动态网页，最后再将处理后的视图返回到请求方[3]。

2.1.2JavaScript
JavaScript 作为一种轻量级的脚本语言， 也是一种嵌入式结构语言。它本身提供的核心语法不算很多，只能用来做一些数学和逻辑运算[5]。
JavaScript，通常缩写为JS，是一种编程语言，与HTML和CSS同时存在于网页前端的编写，是万维网的核心技术之一。绝大多数网站在客户端使用 JavaScript进行网页设计行为，通常包含第三方库。所有专业Web 浏览器有一个专用的JavaScript 引擎来执行用户设备上的代码。JavaScript 是一种高级的、通常是即时编译的语言，它符合ECMAScript标准。它具有动态类型、基于原型的面向对象和一流的功能。它是多范式的，支持事件驱动、函数式和命令式 编程风格。它具有用于处理文本、日期、正则表达式、标准数据结构和文档对象模型的应用程序编程接口(API)[6]。
当前的 JavaScript 生态系统有许多库和框架、已建立的编程实践以及在 Web 浏览器之外大量使用 JavaScript。此外，随着单页应用程序和其他大量 JavaScript 网站的兴起，已经创建了几个转译器来帮助开发过程。
2.1.3spring framework框架
Spring Framework是Java 平台的应用程序框架和依赖注入和控制反转的容器实现。该框架的核心功能可以被任何 Java 应用程序来使用，而且也有一些扩展可用于在Java EE（企业版）平台之上构建 Web 应用程序。尽管该框架没有强加任何特定的编程模型，但它作为Enterprise JavaBeans (EJB) 模型的补充已经在 J​​ava 社区中流行起来。Spring 框架是开源的[7]。
Spring Framework 的核心是它的控制反转(IoC) 容器，它提供了使用反射配置和管理 Java 对象的一致方法。容器负责管理特定对象的对象生命周期：创建这些对象，调用它们的初始化方法，并通过将它们连接在一起来配置这些对象。由容器创建的对象也称为托管对象或bean。可以通过加载XML（可扩展标记语言）文件或检测配置类上的特定Java 注释来配置容器。这些数据源包含提供创建 bean 所需信息的 bean 定义。
Spring 框架有自己的面向切面的编程(AOP) 框架，该框架将切面中的横切关注点模块化。创建一个单独的 AOP 框架的动机来自于这样一种信念，即应该可以提供基本的 AOP 特性，而在设计、实现或配置方面都不会太复杂。Spring AOP 框架还充分利用了 Spring 容器。
Spring 框架具有自己的模型-视图-控制器(MVC) Web 应用程序框架， Spring 开发人员决定编写自己的 Web 框架，因为当时流行的Jakarta Struts Web 框架的糟糕设计，以及其他可用框架的缺陷。除此之外，他们认为表示层和请求处理层之间以及请求处理层和模型之间的分离不够充分。与 Struts 一样，Spring MVC 是一个基于请求的框架。[8]该框架为现代基于请求的框架必须处理的所有职责定义了策略接口。每个接口的目标是简单明了，以便 Spring MVC 用户可以轻松编写自己的实现，如果他们愿意的话。MVC 为更简洁的前端代码铺平了道路。所有接口都与Servlet API紧密耦合。这种与 Servlet API 的紧密耦合被一些人认为是 Spring 开发人员未能为基于 Web 的应用程序提供高级抽象。然而，这种耦合确保了 Servlet API 的特性仍然可供开发人员使用，同时还提供了一个高度抽象的框架来简化使用它。DispatcherServlet 类是框架的前端控制器，负责在HTTP 请求的执行阶段将控制权委派给各种接口[9]。

Mybatis极大的简化了JDBC代码的流程开发，简单易用，易于操作，具有更好的灵活性，通过将SQL定义在XML中的方式能够明显的降低程序的耦合性，并且支持动态SQL，可以根据具体业务需求灵活改变功能，数据的移植性相对于Hibernate更高。
2.1.5 MySQL数据库

第3章   需求分析
需求分析对于系统或软件项目的正常输出有着绝对重要的地位。需求应提前准确的分析记录、以可操作、可运行、可测试、可追溯为原则来与所需要的业务进行综合比较来取得针对系统的各种要求。最好能够充分的对于用户群体和生态背景详细构思内容。
3.1 可行性分析
可行性分析是对于整个平台系统的基本评测评估。可行性分析实质是能够以一种客观理性的角度来具体地表现出现有业务需求的优劣势。
3.1.1技术可行性
本平台的主要用户群体是来自PC浏览器端口，是前后端相互结合开发的应用服务系统。根据目前现有的前后端开发技术和流程设计都已经趋于成熟和完善，完全可以参照现有的开发方法进行功能实现的依据。
对于前端技术而言，目前行业内的设计模式和体系都可以直接拿来借鉴和参考，同时也具有现成的构架模型进行开源使用，能够在短时间内完成页面的开发[12]。而相较于后端的业务逻辑设计，是一些常规的对于相关用户参与的数据的更改，删除，查询，增加的操作。在现目前的技术交流社区中也能够找到很多优秀和强大的设计解决方案来对系统平台的提供支持。
3.1.2经济可行性
本系统投入使用之后，因为平台的主要模块功能是针对个人用户的单项服务
并未考虑商业化改造，主要经济成本只有运行维护的需要和向上服务器的租赁费用，在没有巨额流量冲入的前提下是应该没有特别需要担心的运营费用，所以据此推出经济上面该方案是可以执行的。
3.1.3操作可行性
界面是用户直接进行参与交互的媒介，根据本系统主要面向的服务群体是关于学校师生用户，在设计的过程中本着遵循简洁易懂的原则，通过一些简单的前端交互操作按键可以根据相关直接的提示可以快速地上手进行基本功能如浏览，发帖，跟帖，收藏，修改等相关操作，用户并不需要进行特别的教程学习即可进行使用，能够使得体验感更加优秀。
3.2功能性需求
本平台作为一个校园论坛系统，首先应该与市面上已经存在的论坛系统具备相同的一般性基础功能。该系统首先提供登录的用户自由发帖的权限，根据自己所选择的感兴趣的模块进行帖子内容的填写，这也是本系统最核心的功能，用户也能根据所选的板块查看主题内容有相关联系的帖子列表，关注自己喜欢的博主和收藏自己喜欢的帖子，在个人主页界面中能够查看编辑关于自己的基本信息，管理自己的帖子内容，形成一个完善的社区结构。对于基本的发帖管理，后台管理人员将被赋予权限对待所有的帖子进行审核查看，对论坛社区的环境进行有序的整理，并且还将统一管理所有的主题模块[14]。

（1）运行环境层是在创建web系统程序时，提供给程序运行的支持工具，通过服务器能够保证程序能够在浏览器上的运行效果。

登陆注册模块包含游客角色的注册认证以及登录登出行为操作，游客用户访问首页，开始进行注册时通过Jsp页面中<div>标签进行部分css中的bootstrap框架内容，制作出合适的注册界面形式，用户在注册提示框中输入需要的相关数据，然后调用ajax的方法标准将用户输入的数据进行简单的整合验证处理，通过ajax将固定数据请求方式和内容并对用户名不重复，两次密码保持一致的简单验证处理，正确通过的信息将以POST请求到后端控制层做出后续逻辑处理。登录模式于注册大致相像，也需要通过ajax进行对数据的简单验证通过数据库传来的信息做出对比检测是否含有当前用户。
4.2.2  个人信息管理模块
个人信息管理界面中包含了个人主页的显示，以及对个人信息中的各个数据内容作出修改，在对应的个人主页Jsp页面之中通过镶嵌在<span>标签中的EL表达式获取到当前用户的数据资料，并在合适的<div>标签样式中将个人资料显示在主页中,并且设置编辑按钮跳转到信息编辑页面框,同样以填写正确形式的表单内容提交到后端user控制层重定向到相关修改的业务方法，最后在完成数据变化的保存。
4.2.3  帖子信息模块
此模块内容作为核心业务功能，涵盖整个帖子的浏览，发布，修改和删除以及对他人帖子的评论和收藏。
首页上方导航栏由搜索提示框，根据关键字查询到帖子的数据内容并在首页中列出，用户通过首页上方的发帖按钮选项跳转进入到帖子发布的提示框界面，根据输入提示进行各项内容的输出。在经历正确格式的验证下完成帖子的发布，并将该条帖子的审核状态设置为0（{listArticle.status==0 }）提交到后台管理处待审核，成功通过的帖子的状态信息变更为1，最后成功显示在首页上并显示发帖人和发帖内容。首页帖子顺序按时间先后排序，并且登录用户提供收藏和关注按钮（当前用户不能关注自己和收藏自己的帖子）点击即可在个人主页中保存到相关数据，此时将变更用户或帖子信息状态并发送到后端业务方法中进行数据处理。
在首页中每则帖子末尾显示评论输入框，可以出入数据内容并发表在当前主题帖之后，所有的评论内容都可以在个人主页中查看或删除。
4.2.4 后台信息管理模块
后台管理模块包含的是管理用户的主要业务功能，首先需要进行登录验证信息内容与后台数据检验是否用户该管理用户，点击提交按钮时，触发confirmPass事件，会进行弹框提醒以防无视错误信息提交。
进入后台首页界面之后，左方会显示三项目录选项分别为用户管理，帖子管理和板块管理，点击不同模块会跳转进入对应管理页面，每种数据信息通过基本的表格标签来对应数据的属性，通过EL表达式获取到对应存储的内容并显示到当前页面列表，对于每条信息的任意修改操作都会有提示框来确认是否处理，更改后的内容将会提交到数据后台进行逻辑业务的常规处理并以持久层的方法将变更数据事务提交到数据库。
4.3 系统项目结构设计

第6章 总结和展望
6.1 工作总结
本次设计主要以一个完整的校园论坛系统的实现为目标，开发出了一个具备一般论坛普遍功能的信息交流平台。同时通过简洁的页面设计为平台用户打造出符合操作习惯的网页站点。
本设计的主要工作内容如下：
（1）首先进行对整个论坛平台系统作出相应的需求分析，分别从功能性和非功能性两方面进行了具体的需求统计和分析介绍。
（2）通过之前的需求分析实现了论坛系统所应该具备的各个功能模块，其中主要包括了首页的帖子浏览，个人基本信息管理修改，关键字搜索，板块搜索，帖子信息发布修改，关注收藏列表以及管理用户的审核，用户板块增添等一系列的模块功能展示。
（3）实现了基于 MVC三层架构的设计模式，在整个架构的设计中bean用来存储实体类，还有相应的构造方法。controller层则是用来连接前端和后端的。dao层用来做相关数据的持久化，就是将数据存入到数据库的具体操作及sql。service层则是具体的处理逻辑，将数据处理后重新返回到controller层。程序的整个流程是这样的：接受前端发来的请求，同时向后端发送请求——>service 层——>serviceImpl实现service层,同时连接dao层（在dao层中同样是接口）——>通过dao层去实现对数据库的操作——在XML文件中通过namespace完成连接dao层。
6.2 后续工作展望
本系统还存在着多方面的不足和待完善之处，需要通过后续不断地检验和测试进行更进一步的优化开发。
（1）论坛页面过于简洁，可以在进一步美化界面的布局效果
（2）全局来看，整体功能还待优化和增加，应该可以增加更多丰富的功能操作选项，提高系统的全面性。
（3）数据库索引也能够再次优化设计，提高数据访问的效率
（4）网页有时出现404的错误的空连接状态，可能某些路径容易设置出错找不到对应资源选项，应该进一步完善系统的稳定性，解决目标问题。

Dashrath Mane, Ketaki Chitnis, Namrata Ojha
Spring is the most popular application development framework for enterprise Java. Millions of developers around the world use Spring Framework to create high performing, easily testable, reusable code. Spring framework is an open source Java platform and it was initially written by Rod Johnson and was first released under the Apache 2.0 license in June 2003. Spring is lightweight when it comes to size and transparency. The basic version of spring framework is around 2MB.The core features of the Spring Framework can be used in developing any Java application, but there are extensions for building web applications on top of the Java EE platform. Spring framework targets to make J2EE development easier to use and promote good programming practice by enabling a POJO-based programming model. The Spring Framework provides a comprehensive programming and configuration model for modern Javabased enterprise applications - on any kind of deployment platform. A key element of Spring is infrastructural support at the application level: Spring focuses on the "plumbing" of enterprise applications so that teams can focus on application-level business logic, without unnecessary ties to specific deployment environments. Of course often you want to use O/R (Object Relational) mapping, rather than use relational data access. Your overall application framework must support this also. Thus Spring integrates out of the box with Hibernate (versions 2 and 3), JDO (versions 1 and 2), TopLink and other ORM products. Its data access architecture allows it to integrate with any underlying data access technology. Spring and Hibernate are a particularly popular combination.
Why would you use an ORM product plus Spring, instead of the ORM product directly? Spring adds significant value in the following areas:
Session management. Spring offers efficient, easy, and safe handling of units of work such as Hibernate or TopLink Sessions. Related code using the ORM tool alone generally needs to use the same "Session" object for efficiency and proper transaction handling. Spring can transparently create and bind a session to the current thread, using either a declarative, AOP method interceptor approach, or by using an explicit, "template" wrapper class at the Java code level. Thus Spring solves
many of the usage issues that affect many users of ORM technology.
Resource management. Spring application contexts can handle the location and configuration of Hibernate SessionFactories, JDBC datasources, and other related resources. This makes these values easy to manage and change.Integrated transaction management. Spring allows you to wrap your ORM code with either a declarative, AOP method interceptor, or an explicit 'template' wrapper class at the Java code level. In either case, transaction semantics are handled for you, and proper transaction handling (rollback, etc.) in case of exceptions is taken care of. As we discuss later, you also get the benefit of being able to use and swap various transaction managers, without your ORM-related code being affected. As an added benefit, JDBC-related code can fully integrate transactionally with ORM code, in the case of most supported ORM tools. This is useful for handling functionality not amenable to ORM.Exception wrapping. Spring can wrap exceptions from the ORM layer, converting them from proprietary (possibly checked) exceptions, to a set of abstracted runtime exceptions. This allows you to handle most persistence exceptions, which are non-recoverable, only in the appropriate layers, without annoying boilerplate catches/throws, and exception declarations. You can still trap and handle exceptions anywhere you need to. Remember that JDBC exceptions (including DB specific dialects) are also converted to the same hierarchy, meaning that you can perform some operations with JDBC within a consistent programming model.To avoid vendor lock-in. ORM solutions have different performance other characteristics, and there is no perfect one size fits all solution. Alternatively, you may find that certain functionality is just not suited to an implementation using your ORM tool. Thus it makes sense to decouple your architecture from the toolspecific implementations of your data access object interfaces. If you may ever need to switch to another implementation for reasons of functionality, performance, or any other concerns, using Spring now can make the eventual switch much easier. Spring's abstraction of your ORM tool's Transactions and
Exceptions, along with its IoC approach which allow you to easily swap in mapper/DAO objects implementing data-access functionality, make it easy to isolate all ORM-specific code in one area of your application, without sacrificing any of the power of your ORM tool. The PetClinic sample application shipped with Spring demonstrates the portability benefits that Spring offers, through providing variants that use JDBC, Hibernate, TopLink and Apache OJB to implement the persistence layer.Ease of testing. Spring's inversion of control approach makes it easy to swap the implementations and locations of resources such as Hibernate session factories, datasources, transaction managers, and mapper object implementations (if needed). This makes it much easier to isolate and test each piece of persistence-related code in isolation.Above all, Spring facilitates a mix-and-match approach to data access. Despite the claims of some ORM vendors, ORM is not the solution to all problems, although it is a valuable productivity win in many cases. Spring enables a consistent architecture, and transaction strategy, even if you mix and match persistence approaches, even without using JTA.Abstracting a data access API is not enough; we also need to consider transaction management. JTA is the obvious solution, but it's a cumbersome API to use directly, and as a result many J2EE developers used to feel that EJB CMT is the only rational option for transaction management. Spring has changed that.
Spring's transaction abstraction is unique in that it's not tied to JTA or any other transaction management technology. Spring uses the concept of a transaction strategy that decouples application code from the underlying transaction infrastructure (such as JDBC).
