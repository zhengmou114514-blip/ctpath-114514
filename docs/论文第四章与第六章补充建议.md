# 论文第四章与第六章补充建议

## 1. 问题分析

当前论文初稿第四章已经说明了总体架构、功能结构、角色权限、数据库和接口设计，但图表支撑偏少。系统设计类参考论文通常会在总体设计章节放置功能结构图、业务流程图、模块流程图和 E-R 图，在测试章节放置分模块测试用例表。结合当前项目代码，本文不宜画成综合 HIS，而应围绕慢病辅助诊疗业务闭环展开。

当前项目已具备以下真实模块依据：

- 前端路由：登录、医生首页、患者详情、患者档案、随访工作台、模型洞察、模型看板、模型调试台、训练中心、治理看板、药品目录、药品权限。
- 后端接口：认证、患者、预测、附件、随访工单、联系记录、药品目录、药品权限、药房扩展、治理、审计、模型指标。
- 数据库脚本：`doctor_users`、`roles`、`patients`、`patient_events`、`patient_attachments`、`outpatient_tasks`、`patient_contact_logs`、`drug_catalog`、`drug_permissions`、`patient_medications`、`prediction_results`、`governance_records`、`system_audit_logs`。
- openhis 可参考的逻辑：系统管理、角色授权、药品基础资料、药品剂型/单位/用法等按模块拆分；本项目只吸收“模块化和权限边界”，不照搬收费、住院、医保结算等大型 HIS 范围。

## 4. 数据库拆分建议

当前 `patients` 表承担了患者主索引、联系方式、紧急联系人、医保、建档状态、病史摘要、慢病状态等多类职责。论文中建议拆分为以下逻辑表，既符合医院业务分层，也更接近 openhis 中“基础资料、授权、业务记录分离”的组织方式：

| 表名 | 职责 | 与当前字段对应 |
|---|---|---|
| `patients` | 患者主索引与慢病核心状态 | `patient_id`、`name`、`gender`、`age`、`primary_disease`、`current_stage`、`risk_level`、`last_visit` |
| `patient_profiles` | 联系方式与身份扩展 | `phone`、`identity_masked`、`insurance_type`、`emergency_contact_*` |
| `patient_archives` | 建档与病案状态 | `medical_record_number`、`archive_source`、`archive_status`、`consent_status`、`department`、`primary_doctor`、`case_manager` |
| `patient_medical_histories` | 病史摘要与数据支撑 | `allergy_history`、`family_history`、`summary`、`data_support` |
| `patient_events` | 病程时间线与模型输入事件 | `event_time`、`relation`、`object_value`、`source`、`confidence` |
| `patient_attachments` | 电子档案附件 | 附件类型、文件名、MIME、大小、预览地址、上传人 |
| `outpatient_tasks` | 随访/复查任务 | 任务类别、负责人、到期日、优先级、状态 |
| `patient_contact_logs` | 随访联系记录 | 联系方式、联系对象、结果、下次联系时间 |
| `drug_catalog` | 药品目录 | 通用名、商品名、剂型规格、处方药、管制药、状态 |
| `drug_permissions` | 药品角色权限 | 医生、护士、药师、档案员、管理员权限 |
| `patient_medications` | 当前用药 | 患者、药品、剂量、频次、审核状态 |
| `prediction_results` | 预测结果留痕 | 策略、Top-K、证据、建议、相似病例 |
| `governance_records` | 数据治理记录 | 缺失字段、冲突、异常、处理状态 |

论文写法建议：可以在论文中采用“逻辑拆分后的数据库设计”，同时说明当前工程为兼顾演示和兼容性，在 `mysql_schema.sql` 中仍保留部分聚合字段，后续可通过迁移脚本演进为拆分表结构。这样不会夸大当前代码，也能体现数据库设计能力。

建议将第六章从“总体功能测试”改成“分模块测试 + 接口合同测试 + 模型结果分析”。

| 测试模块 | 测试点 | 期望结果 | 项目依据 |
|---|---|---|---|
| 登录认证模块 | 正确账号登录、未登录访问保护路由、退出登录 | 返回 token，路由守卫生效，退出后回登录页 | `test_login.py`、`AppBootstrap.spec.ts` |

| 电子档案附件模块 | 上传合法附件、列表展示、预览、拒绝非法类型 | 合法文件成功，非法类型返回 415 | `test_patient_attachments.py` |
| 随访工作台模块 | 待随访任务、联系记录、任务完成/关闭 | 任务状态正确变化并保留日志 | `test_backend_contracts.py`、随访页面测试 |

| 药品权限模块 | 角色权限查询与更新、管制药权限判断 | 医生/护士/药师权限边界正确 | `test_drug_permissions.py` |

## 6. 验收清单

- 第四章至少有 5 类图：功能结构图、核心业务流程图、模块流程图、模型治理边界图、数据库 E-R 图。
- 图中不出现收费、住院、医保结算等综合 HIS 模块。
- 模型洞察只画当前患者；模型看板只画全局指标；治理看板只画数据质量。
- ER 图中患者主索引、档案、附件、病程事件、随访、药品、预测结果、治理记录边界清晰。
- 第六章测试按模块拆分，不再只写一条总业务闭环。
- 测试内容能对应项目中的实际测试文件和接口，避免虚构接口或虚构功能。
