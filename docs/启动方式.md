# 启动方式

本文档用于说明当前项目的启动地址、启动顺序、数据库模式和权限边界。

## 1. 服务地址

### clinic-web 医生业务端
- 默认地址: `http://127.0.0.1:5173`
- 入口命令: `npm run dev`

### model-web 模型管理端
- 默认地址: `http://127.0.0.1:5174`
- 入口命令: `npm run dev:model`

### clinic-api 业务后端
- 默认地址: `http://127.0.0.1:8000`
- OpenAPI: `http://127.0.0.1:8000/docs`

### model-api 模型后端
- 默认地址: `http://127.0.0.1:8001`
- OpenAPI: `http://127.0.0.1:8001/docs`

## 2. 推荐启动顺序

### 2.1 仅启动后端
适合调试接口、校验数据库、查看 OpenAPI。

```powershell
cd E:\CTpath-master
conda activate ctpath
cd E:\\CTpath-master\\backend
cd E:\\CTpath-master\\backend
cd E:\CTpath-master\backend
cd E:\CTpath-master\backend
uvicorn app.main:app --reload --port 8000
```

```powershell
cd E:\CTpath-master
conda activate ctpath
uvicorn model_api.main:app --reload --port 8001
```

启动后可直接访问：
- `http://127.0.0.1:8000/docs`
- `http://127.0.0.1:8001/docs`

### 2.2 后端 + 前端一起启动
适合演示、答辩和业务联调。

1. 先启动 `clinic-api`
2. 再启动 `model-api`
3. 再启动 `clinic-web`
4. 再启动 `model-web`

```powershell
cd E:\CTpath-master\frontend
npm install
npm run dev
```

```powershell
cd E:\CTpath-master\frontend
npm run dev:model
```

## 3. 数据库模式

系统支持两种业务数据源模式：

- `demo`：不配置数据库时使用内置演示数据
- `mysql`：配置 `CTPATH_DB_URL` 后使用 MySQL 持久化数据

### 3.1 MySQL 配置示例

```powershell
$env:CTPATH_DB_URL="mysql+pymysql://root:your_password@127.0.0.1:3306/ctpath?charset=utf8mb4"
cd E:\\CTpath-master\\backend
cd E:\\CTpath-master\\backend
cd E:\CTpath-master\backend
cd E:\CTpath-master\backend
uvicorn app.main:app --reload --port 8000
```

如需初始化示例数据，可以执行：

```powershell
Get-Content .\backend\app\mysql_schema.sql | mysql -u root -p ctpath
Get-Content .\backend\app\mysql_seed_demo.sql | mysql -u root -p ctpath
```

### 3.2 模式判断
- `GET /api/health` 返回 `mode=demo` 表示当前使用演示数据
- `GET /api/health` 返回 `mode=mysql` 表示当前已切换到 MySQL

## 4. 角色与权限

当前系统按“医生业务端 + 模型管理端 + 后台管理”拆分权限。

### 4.1 医生角色
- 可访问: 医生工作台、患者详情、患者档案、电子病历、随访工作台、模型洞察
- 主要职责: 诊疗、预测查看、随访处理、档案查看、当前用药评估
- 不直接承担: 药品目录维护、药品权限矩阵维护、模型训练任务管理

### 4.2 护士角色
- 可访问: 随访任务、联系方式、病情流转
- 主要职责: 联系、记录、任务跟进、状态更新

### 4.3 档案员角色
- 可访问: 患者档案、电子附件、药品目录、药品权限、数据质量、治理看板
- 主要职责: 档案维护、附件上传、药品目录维护、权限维护、数据治理

### 4.4 管理员角色
- 可访问: 医生端全部模块 + 模型管理端全部模块
- 主要职责: 系统配置、权限配置、数据治理、模型治理、运行监控

## 5. 后台管理入口

### clinic-web 后台管理
适合医院业务侧使用，主要包含：
- 患者档案
- 电子病历
- 电子附件
- 随访工作台
- 药品目录
- 药品权限

### model-web 后台管理
适合模型管理侧使用，主要包含：
- 数据集管理
- 训练任务
- 模型版本
- 模型运营台
- 推理服务状态

## 6. 推荐验收路径

1. 先启动 `clinic-api` 和 `model-api`
2. 再启动 `clinic-web` 和 `model-web`
3. 登录医生端，确认：
   - 患者列表可点开
   - 患者档案可查看、可打印
   - 随访任务、联系方式、病情流转可直达
   - 电子病历可切换
4. 登录模型端，确认：
   - 数据集、训练任务、模型版本、运营台可切换
5. 如需真实持久化，切换到 MySQL 模式后再验收一次

## 7. 备注

- 业务端默认地址是 `5173`
- 模型端默认地址是 `5174`
- 业务后端默认地址是 `8000`
- 模型后端默认地址是 `8001`
- 若仅启动后端，适合检查接口；若要做界面管理，必须同时启动对应前端
