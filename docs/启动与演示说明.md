# 启动与演示说明

最后更新：2026-04-21

本文档说明当前仓库的真实运行方式。项目是慢病辅助诊疗业务系统，不是完整 HIS。

## 1. 后端启动

Python 依赖由 conda 环境管理。

```powershell
cd E:\CTpath-master
conda activate ctpath
cd E:\\CTpath-master\\backend
cd E:\CTpath-master\backend
uvicorn app.main:app --reload
```

默认地址：

- API: `http://127.0.0.1:8000`
- OpenAPI: `http://127.0.0.1:8000/docs`

后端入口：

- `backend/app/main.py`

当前主要中间件：

- `TraceIdMiddleware`
- `GlobalExceptionMiddleware`
- `JWTAuthMiddleware`
- `CORSMiddleware`
- SlowAPI rate limit handler

当前主要 API：

- `analytics`
- `attachments`
- `audit`
- `auth`
- `authz`
- `drug_permissions`
- `drugs`
- `governance`
- `patient_medications`
- `patients`
- `predictions`
- `worklists`

默认地址：

## 3. demo / mysql 模式

系统根据 `CTPATH_DB_URL` 判断运行模式。

### demo 模式

不配置 `CTPATH_DB_URL` 时使用 demo store。

特征：

- 启动快
- 适合演示
- `/api/health` 返回 `mode=demo`

### mysql 模式

配置 `CTPATH_DB_URL` 后使用 MySQL。

示例：

```powershell
$env:CTPATH_DB_URL="mysql+pymysql://root:your_password@127.0.0.1:3306/ctpath?charset=utf8mb4"
cd E:\\CTpath-master\\backend
cd E:\CTpath-master\backend
uvicorn app.main:app --reload
```

初始化示例：

```powershell
Get-Content .\backend\app\mysql_schema.sql | mysql -u root -p ctpath
Get-Content .\backend\app\mysql_seed_demo.sql | mysql -u root -p ctpath
```

## 5. 当前主要演示路径

### 医生路径

1. 打开 `/login`
2. 使用 `demo_clinic / demo123456` 登录
3. 进入医生工作台
4. 选择待处理患者
5. 打开患者详情

7. 可进入模型洞察、药品管理、药品权限、治理中心

### 当前最小业务闭环验收

1. 打开 `/login`
   预期：显示登录页。
   若失败：优先看后端是否已启动、浏览器 Console 是否有接口连接错误。

2. 使用 `demo_clinic / demo123456` 登录
   预期：进入 `/` 对应的工作台页面。
   若失败：优先看 `/api/login` 返回状态与浏览器 Network。

3. 在医生工作台打开任一患者详情
   预期：路由变为 `/patient-detail/:patientId`。
   若失败：优先看 `frontend/src/pages/AppWorkspacePage.vue` 的 `handleOpenPatientDetail()`。

4. 初次进入患者详情时，先观察预测区域
   预期：显示 `Preloaded Summary`，表示当前还是预置摘要，不代表已经调用真实预测。
   若失败：优先看 `frontend/src/pages/PatientDetailPage.vue` 的 `predictionSource`。

5. 点击 `Run Prediction`
   预期：按钮进入 loading，预测来源状态切到 `Predicting`。
   若失败：优先看 `workspace.runPrediction()` 是否被触发。

6. 打开浏览器 Network
   预期：能看到真实 `POST /api/predict` 请求，返回 `200`。
   若失败：优先看后端 `/api/predict`、前端 `frontend/src/services/api.ts` 的 `predictPatient()`。

7. 观察预测区域
   预期：状态切到 `Latest Prediction`，预测卡片和建议区域更新为最新接口结果。
   若失败：优先看 `workspace.predictionResult` 是否写入，以及 `PatientDetailPage.vue` 的 `latestPrediction` 计算。

8. 模拟失败场景
   做法：临时停掉后端服务，或让 `/api/predict` 返回错误后再点击 `Run Prediction`。
   预期：页面显示 `Prediction Failed`，并明确说明当前仍在显示预置摘要或上次成功结果。
   若失败：优先看 `frontend/src/composables/useWorkspaceController.ts` 的 `predictionError`。

9. 点击侧边栏退出登录
   预期：立即跳转到 `/login`，而不是停留在 `/` 或 handoff 文案。
   若失败：优先看 `frontend/src/pages/AppWorkspacePage.vue` 的 `handleLogout()`。

10. 在 `/login` 页面刷新，或尝试直接访问受保护页
   预期：不能直接回到仍可用的已登录工作台，需要重新登录。
   若失败：优先看 `localStorage` 中 `ctpath.auth.session` 是否已清除，以及 `frontend/src/router/index.ts` 的登录守卫。
